Modernization Workbench UI and Agentic Architecture

A guided app experience for COBOL-to-Java modernization, backed by one user-visible agentic system with graph tools, OS workspace tools, build tools, validation gates, and auditable evidence.

Recommendation Build on the existing Next.js + React + FastAPI + Neo4j project. Frontend choice Next.js App Router, React 19, TypeScript, Tailwind, lucide icons. Alternative Vite only if this becomes a pure SPA with no server-rendered artifacts or app-level routing needs. Date 2026-05-30

Framework Decision

Use Next.js, not Vite, for the product app. The current reusable source-graph UI is already on Next.js 15.3, React 19.1, Tailwind 4, and Turbopack. The product needs persistent route-based journeys, server-rendered HTML artifact pages, deep links into graph/artifact views, auth-ready layouts, and deployment flexibility. Those are Next.js strengths.

OptionFitDecision
Next.js App Router Best fit for a product workbench with layouts, nested routes, server/client component boundaries, artifact pages, and existing reuse. Recommended. Continue from source_graphs_v1.0/web and evolve it into the modernization workbench.
Vite + React Router Excellent for fast pure-SPA development, especially if all backend work stays in FastAPI and the frontend is only a client shell. Good fallback for a lighter prototype, but it discards useful existing Next.js structure.
TanStack Start Promising full-stack React alternative, but less aligned with the existing codebase and still more moving-target risk for an enterprise product. Do not pick for v1 unless there is a strong team preference.
Practical architecture: keep FastAPI as the agent/job/graph backend. Use Next.js for the app shell, guided workflow, artifact views, graph explorer, and real-time job status. Avoid pushing agent execution into Next.js server functions.

Single Agentic System

The user should see one agent: the Modernization Agent. Internally it has a planner, memory, tool router, phase policies, and task-scoped workers, but the product experience is one agentic system operating inside a controlled workspace, like Claude Code or Codex for modernization.

User Surface

  • Agent console
  • Run buttons per stage
  • Approval gates
  • Artifact comments
  • Evidence explanations

Modernization Agent Runtime

  • Planner: creates a stage plan and checkpoints.
  • Tool router: selects graph, OS, build, parser, judge, or deploy tools.
  • Context manager: compresses graph traversals and preserves lineage.
  • Policy engine: controls read/write/build/deploy permissions by phase.
  • Verifier: runs hard gates before marking work complete.
  • Audit recorder: stores tool calls, model, prompts, costs, approvals.

Important Distinction

Use one user-visible agent, but allow internal scoped workers for parallel map/reduce jobs. For example, one BRD subsystem worker per graph cluster is fine if all workers are spawned by the Modernization Agent, share the same policy engine, write structured outputs, and cannot bypass gates.

Codex-Inspired Runtime

Use openai/codex as a strong design reference for the agent substrate. Codex is a local coding agent with a terminal/app workflow, workspace tools, approvals, sandboxing, MCP, skills, subagents, hooks, and configuration through project/user context. The modernization app should adopt those product mechanics, while replacing generic coding goals with COBOL-modernization stages and graph-grounded evidence gates.

Conversation plus workspace

The agent conversation is not separate from the project. Every message, plan, command, patch, generated artifact, build log, graph query, and approval belongs to a workspace snapshot.

Permission profiles

Mirror Codex-style profiles: read-only investigation, workspace-write generation, build/test execution, network-restricted retrieval, and deploy-capable mode. The active profile should be visible in the UI at all times.

Approval overlay

When the agent wants to write files, run expensive jobs, access network, execute generated code, or deploy, surface a specific approval request with command, path, risk, and expected result.

Policy inheritance

Internal workers inherit the parent run's sandbox and approval policy. A BRD subsystem worker or codegen repair worker cannot silently gain broader permissions than the main agent.

Project instructions

Support a project-scoped modernization instruction file, similar in spirit to AGENTS.md, for coding standards, target architecture, model routing, migration constraints, and client-specific glossary.

Tool transparency

Expose tool calls in the UI as readable events: graph query, source search, parser run, patch, compile, judge, equivalence run. Hide raw noise by default, but make full logs inspectable.

Runtime Components

ComponentCodex-inspired behaviorModernization-specific behavior
Session manager Maintains conversation state, current workspace, active permissions, and resumable runs. Pins every run to graph snapshot, source snapshot, artifact versions, and modernization stage.
Plan loop Turns user intent into a visible plan, updates status while tools run, and reports completion evidence. Plans are stage-aware: parse plan, blueprint plan, seam plan, story plan, build plan, verify plan.
Tool broker Routes shell, patch, MCP, browser, and other tools through one permissioned interface. Adds graph, COBOL parser, artifact, judge, Java build, and equivalence harness tools.
Sandbox executor Runs commands under filesystem/network policy and refuses unsupported policies instead of silently bypassing them. Separates source-read workspace, generated-code workspace, build workspace, and deployment workspace.
Subagent runner Spawns specialized workers only for explicitly parallel work and consolidates results into one response. Uses workers for subsystem analysis, seam scoring, story cluster generation, and test generation.
Audit recorder Stores tool calls, approvals, command outputs, diffs, and result summaries. Adds lineage: requirement-to-source, seam-to-graph, test-to-business-rule, code-to-story.

Tool Policy

  • Default all graph and source investigation tools to read-only.
  • Allow shell-style OS tools, but wrap them with workspace scope, command allowlists, timeout limits, log capture, and artifact linkage.
  • Separate inspect, write, build, and deploy permissions so the UI can show exactly what the agent is allowed to do.
  • Require every generated artifact to include graph snapshot ID, source refs, model, prompt version, token usage, and judge report.
  • Use checkpointed sessions so a long modernization run can resume with the same graph snapshot and artifact state.

Build Sequence

  1. Rename/re-skin the existing app shell into Modernization Workbench while keeping the current graph UI working.
  2. Add workspace and journey-stage routes: /workspaces, /workspaces/[id]/journey/[stage], /workspaces/[id]/artifacts/[artifactId].
  3. Add the persistent journey rail, stage header/gates, agent console, and evidence drawer.
  4. Promote current repo ingest, graph, ask-codebase, and BRD panel into journey stages.
  5. Add AgentRun storage and live status events so the UI can show plans, tool calls, costs, and results.
  6. Add seam studio and blueprint approval before code/design generation.
  7. Add isolated codegen/build workspaces only after the blueprint and seam artifacts are stable.
